# Журнал работ Telegram Mini App

## Правило перехода

Работа ведётся строго по этапам. Следующий этап начинается только после явного подтверждения владельца. Записи не содержат секретов, личных идентификаторов, адресов gateway или production-данных.

## Статус этапов

| Этап | Статус | Результат |
| --- | --- | --- |
| 0. Обследование и проектирование | Завершён | Прочитаны обязательные документы, проверены Git и архитектура, проведено интервью, выбраны стек и принципы API/безопасности, подготовлены карта экранов, этапы и UAT-критерии. |
| 1. Детализация UX и API-контракта | Завершён | Детальная карта переходов, модели данных API и OpenAPI contract без реализации. |
| 2. Общий backend и безопасный API | Завершён | Локальная защищённая основа API, migration v6 и автоматические проверки; production не затрагивался. |
| 3. Пользовательский frontend | Не начат | React + TypeScript + Vite. |
| 4. Административный frontend | Не начат | Полный role-aware интерфейс. |
| 5. Локальная интеграция и UAT | Не начат | Изолированная локальная проверка без production. |
| 6. CI/CD и production-выпуск | Не начат | Только после завершения GitHub Environment/secrets/protection и отдельного подтверждения. |

## 8 августа 2026 — этап 0 завершён

- Подтверждена работа в ветке `dev`; до начала подготовки рабочее дерево было чистым.
- Подтверждено: Mini App включает пользовательскую и полную административную роли с первого релиза; бот остаётся действующим параллельным интерфейсом.
- Выбран адаптивный дизайн на основе публичного сайта, с приоритетом мобильного Telegram и полноценным desktop/tablet режимом.
- Выбран стек React + TypeScript + Vite и REST API v1 на общем Python backend.
- Зафиксирована серверная проверка Telegram `initData`, короткая сессия, CSRF, идемпотентность и запрет раскрытия календарных данных.
- Рекомендован production-домен `calendar.yibogdanovskaya.ru`; локальная разработка и тестирование предшествуют любой серверной работе.
- Создан локальный ignored-файл `.env` без секретов. Google OAuth-токен и общий секрет Apps Script остаются отдельными ignored-файлами, на которые ссылается `.env`.

## 8 августа 2026 — локальная конфигурация проверена

- Владелец заполнил `BOT_TOKEN`, `ADMIN_TELEGRAM_ID` и `APPS_SCRIPT_URL` в локальном `.env`.
- Без вывода значений подтверждены: наличие токена, числовой формат Telegram ID, формат Apps Script Web App endpoint с `/exec`, наличие и непустое состояние локального файла общего секрета.
- Локальные пути базы и журнала заданы; сетевых запросов и изменений Google Calendar не выполнялось.

## 8 августа 2026 — этап 1 завершён

- Подготовлена UX-карта с mobile и desktop навигацией, пользовательскими и административными маршрутами, состояниями ошибок и адаптивностью.
- Подготовлен API-контракт v1: auth, сессия, CSRF, идемпотентность, пользовательские и административные endpoint'ы, модели, ошибки и правила согласованности.
- Подтверждено: документы не являются реализацией; существующий бот, backend, база, CI и сервер не изменялись.

## 8 августа 2026 — этап 2 начат

- Владелец подтвердил изменения вне `miniapp/` для локального защищённого backend API.
- Добавлены проектируемая migration v6 для хэшированных Mini App-сессий и идемпотентного создания заявки, отдельный ASGI entry point и общий сервис пользовательского бронирования.
- Добавлены только локальные зависимости FastAPI/Uvicorn и изолированные тесты; запуск и установка зависимостей ожидают доступного Python 3.12 в локальном окружении.

## 8 августа 2026 — этап 2 завершён локально

- Установлен локальный Python 3.12.10 из официального установщика; создано ignored-виртуальное окружение `.venv`. Секреты не выводились и не добавлялись в Git.
- Добавлены FastAPI/ASGI entry point и общий сервис бронирования. Существующий long-polling бот, его кнопки, тексты и навигация не менялись.
- Реализованы серверная проверка Telegram `initData`, короткие hash-only сессии, `HttpOnly` cookie, CSRF, запрет межсайтовых mutation, серверное определение роли и безопасные ответы без содержимого личного Google Calendar.
- Добавлена транзакционная migration v6 для Mini App-сессий и идемпотентного создания заявки; повторная отправка того же действия не создаёт второй резерв. Создание и отмена используют существующую автоматизацию pending-напоминаний.
- Реализована и проверена локальная основа маршрутов auth, consent, `me`, доступности, пользовательских pending-заявок. Альтернативы, change requests, privacy deletion и административные маршруты остаются целевыми частями контракта и будут реализованы вместе с этапами 3 и 4.
- Исправлено освобождение локальных SQLite-подключений после транзакций и в health-check; это устраняет блокировку временных файлов на Windows и не меняет предметные правила приложения.
- Самостоятельные проверки: scan секретов, `compileall`, полный набор из 81 Python-теста, а также отдельные HTTP contract tests (подпись Telegram, сессия, CSRF, чужая заявка/IDOR, идемпотентность). Все завершились успешно.
- На сервер, в `main` и в GitHub ничего не развёртывалось. Далее требуется отдельное подтверждение владельца для этапа 3 — пользовательского frontend.
