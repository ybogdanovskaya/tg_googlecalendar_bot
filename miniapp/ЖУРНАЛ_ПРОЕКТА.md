# Журнал работ Telegram Mini App

## Правило перехода

Работа ведётся строго по этапам. Следующий этап начинается только после явного подтверждения владельца. Записи не содержат секретов, личных идентификаторов, адресов gateway или production-данных.

## Статус этапов

| Этап | Статус | Результат |
| --- | --- | --- |
| 0. Обследование и проектирование | Завершён | Прочитаны обязательные документы, проверены Git и архитектура, проведено интервью, выбраны стек и принципы API/безопасности, подготовлены карта экранов, этапы и UAT-критерии. |
| 1. Детализация UX и API-контракта | Завершён | Детальная карта переходов, модели данных API и OpenAPI contract без реализации. |
| 2. Общий backend и безопасный API | Завершён | Локальная защищённая основа API, migration v6 и автоматические проверки; production не затрагивался. |
| 3. Пользовательский frontend | Завершён | Полный пользовательский интерфейс и API-операции, статическая сборка и локальные тесты. |
| 4. Административный frontend | Завершён локально | Role-aware dashboard, заявки, ручные встречи, серии, настройки, статистика и безопасная проверка интеграции. |
| 5. Локальная интеграция и UAT | Завершён локально | Изолированные API и frontend-сценарии, статическая сборка, проверки секретов и регрессия без production. |
| 6. CI/CD и production-выпуск | Частично завершён | Frontend CI выполнен в GitHub Actions; изолированный HTTPS preview и production не начаты. |

## 8 августа 2026 — этап 0 завершён

- Подтверждена работа в ветке `dev`; до начала подготовки рабочее дерево было чистым.
- Подтверждено: Mini App включает пользовательскую и полную административную роли с первого релиза; бот остаётся действующим параллельным интерфейсом.
- Выбран адаптивный дизайн на основе публичного сайта, с приоритетом мобильного Telegram и полноценным desktop/tablet режимом.
- Выбран стек React + TypeScript + Vite и REST API v1 на общем Python backend.
- Зафиксирована серверная проверка Telegram `initData`, короткая сессия, CSRF, идемпотентность и запрет раскрытия календарных данных.
- Рекомендован production-домен `calendar.yibogdanovskaya.ru`; локальная разработка и тестирование предшествуют любой серверной работе.
- Создан локальный ignored-файл `.env` без секретов. Google OAuth-токен и общий секрет Apps Script остаются отдельными ignored-файлами, на которые ссылается `.env`.

## 8 августа 2026 — локальная конфигурация проверена

- Владелец заполнил `BOT_TOKEN`, `ADMIN_TELEGRAM_ID` и `APPS_SCRIPT_URL` в локальном `.env`.
- Без вывода значений подтверждены: наличие токена, числовой формат Telegram ID, формат Apps Script Web App endpoint с `/exec`, наличие и непустое состояние локального файла общего секрета.
- Локальные пути базы и журнала заданы; сетевых запросов и изменений Google Calendar не выполнялось.

## 8 августа 2026 — этап 1 завершён

- Подготовлена UX-карта с mobile и desktop навигацией, пользовательскими и административными маршрутами, состояниями ошибок и адаптивностью.
- Подготовлен API-контракт v1: auth, сессия, CSRF, идемпотентность, пользовательские и административные endpoint'ы, модели, ошибки и правила согласованности.
- Подтверждено: документы не являются реализацией; существующий бот, backend, база, CI и сервер не изменялись.

## 8 августа 2026 — этап 2 начат

- Владелец подтвердил изменения вне `miniapp/` для локального защищённого backend API.
- Добавлены проектируемая migration v6 для хэшированных Mini App-сессий и идемпотентного создания заявки, отдельный ASGI entry point и общий сервис пользовательского бронирования.
- Добавлены только локальные зависимости FastAPI/Uvicorn и изолированные тесты; запуск и установка зависимостей ожидают доступного Python 3.12 в локальном окружении.

## 8 августа 2026 — этап 2 завершён локально

- Установлен локальный Python 3.12.10 из официального установщика; создано ignored-виртуальное окружение `.venv`. Секреты не выводились и не добавлялись в Git.
- Добавлены FastAPI/ASGI entry point и общий сервис бронирования. Существующий long-polling бот, его кнопки, тексты и навигация не менялись.
- Реализованы серверная проверка Telegram `initData`, короткие hash-only сессии, `HttpOnly` cookie, CSRF, запрет межсайтовых mutation, серверное определение роли и безопасные ответы без содержимого личного Google Calendar.
- Добавлена транзакционная migration v6 для Mini App-сессий и идемпотентного создания заявки; повторная отправка того же действия не создаёт второй резерв. Создание и отмена используют существующую автоматизацию pending-напоминаний.
- Реализована и проверена локальная основа маршрутов auth, consent, `me`, доступности, пользовательских pending-заявок. Альтернативы, change requests, privacy deletion и административные маршруты остаются целевыми частями контракта и будут реализованы вместе с этапами 3 и 4.
- Исправлено освобождение локальных SQLite-подключений после транзакций и в health-check; это устраняет блокировку временных файлов на Windows и не меняет предметные правила приложения.
- Самостоятельные проверки: scan секретов, `compileall`, полный набор из 81 Python-теста, а также отдельные HTTP contract tests (подпись Telegram, сессия, CSRF, чужая заявка/IDOR, идемпотентность). Все завершились успешно.
- На сервер, в `main` и в GitHub ничего не развёртывалось. Далее требуется отдельное подтверждение владельца для этапа 3 — пользовательского frontend.

## 8 августа 2026 — этап 3 начат

- Локально установлен Node.js 24.19.0 LTS из официального подписанного установщика только для frontend-сборки и тестов. На VPS Node.js не устанавливался.
- В `miniapp/` создан статический React + TypeScript + Vite-каркас, собственные адаптивные стили и безопасный API-клиент без секретов в bundle.
- Реализованы экраны защищённого запуска через Telegram, согласия, главной, создания заявки, списка своих заявок, отмены pending-заявки, справки и состояний загрузки/ошибки/пустого результата.
- Свободные даты, слоты, правила и статусы frontend получает только от backend; содержимое Google Calendar не запрашивается и не отображается.
- Локальная сборка `npm run build` и frontend unit-тест `npm test` успешно завершены. Артефакт `dist/` и зависимости игнорируются Git.

## 8 августа 2026 — этап 3 завершён локально

- Реализованы пользовательские API-операции: просмотр и принятие/отклонение альтернатив, запрос переноса или отмены назначенной встречи, актуальная информация о политике и создание/подтверждение запроса удаления данных.
- Операции проверяют владельца объекта на сервере, используют CSRF и `Idempotency-Key`, повторно проверяют доступность через backend и не возвращают содержимое Google Calendar.
- Пользовательский React-интерфейс подключён к этим операциям: редактирование pending-заявки, выбор альтернативы, запрос переноса через серверные слоты, запрос отмены и двухшаговое подтверждение удаления данных.
- Проверки: `npm run build`, `npm test`, целевые API-тесты и полный Python-регрессионный набор из 85 тестов, scan секретов и `compileall` — успешно. Сервер, `main`, production и действующий интерфейс чат-бота не менялись.
- Далее требуется отдельное подтверждение владельца для этапа 4 — административного интерфейса.

## 8 августа 2026 — этап 4 начат

- Владелец подтвердил переход к административному интерфейсу и связанным защищённым API-операциям.
- Подтверждено, что Mini App использует существующие `Database`, `AutomationStore`, правила бронирования и `CalendarClient`; новая база и дублирование бизнес-правил не создаются.
- Первая внутренняя часть этапа: dashboard, обработка заявок и альтернатив, настройки доступности, закрытые даты и статистика. Затем — ручные встречи, серии и безопасные подтверждения конфликтов.

## 8 августа 2026 — этап 4 завершён локально

- Реализованы и защищены серверной ролью `ADMIN`: dashboard, pending-заявки, альтернативы, запросы на перенос и отмену, ручные встречи, серии, настройки записи и закрытые даты.
- Административный React-интерфейс показывает эти операции только после серверной проверки Telegram `initData`; он не возвращает содержимое личного Google Calendar.
- Добавлены редактирование pending-заявки и ручной встречи, просмотр и перенос/отмена отдельного повторения, агрегированная статистика и статус интеграции без выдачи данных календаря.
- Проверки: 13 API-тестов, 2 frontend-теста, frontend build, scan секретов, `compileall` и полный Python-регрессионный набор из 91 теста успешно пройдены. Production, `main` и действующий интерфейс чат-бота не изменялись.
- Этап 5 (локальная интеграция и UAT) не начат: для него требуется отдельное явное подтверждение владельца.

## 8 августа 2026 — этап 5 завершён локально

- Подготовлен [чек-лист локальной интеграции и UAT](docs/ЭТАП_5_UAT_ЧЕК_ЛИСТ.md), который явно разделяет изолированные автоматические проверки и будущую ручную проверку в Telegram.
- Добавлены frontend-сценарии защищённого запуска: приложение вне Telegram не открывает кабинет; пользовательская роль не получает административную навигацию; роль `ADMIN` приходит только через server-side API и открывает административный экран.
- Найден и исправлен дефект подписи административной навигации: Unicode-последовательности заменены корректным русским текстом.
- Проверки: scan секретов, `compileall`, полный Python-регрессионный набор из 91 теста, 5 frontend-тестов, static build и отдельный поиск маркеров секретов в `dist/` успешно завершены.
- Реальный Telegram WebView, HTTPS preview, CI/CD, сервер, `main` и production не затрагивались. Они требуют отдельной инфраструктуры и отдельного подтверждения владельца.

## 8 августа 2026 — этап 6 начат: проектирование CI и preview

- Проверены существующие GitHub workflows: текущий CI проверяет Python, а production workflow не включает Mini App, не запускается автоматически и не затрагивался.
- Подготовлен [план этапа 6](docs/ЭТАП_6_CI_И_PREVIEW_ПЛАН.md): минимальная frontend CI-задача на GitHub-hosted runner, без secrets, VPS, Google Calendar и deploy.
- Зафиксировано различие между безопасной CI-проверкой и будущим HTTPS preview: для реального Telegram UAT понадобятся отдельные тестовые домен, бот, данные и изолированная серверная конфигурация.
- Изменение `.github/workflows/ci.yml` отложено до отдельного согласования, так как этот файл находится вне `miniapp/`.

## 8 августа 2026 — этап 6, подзадача 6.1 завершена: frontend CI

- После подтверждения владельца обновлён `.github/workflows/ci.yml`: добавлена независимая `Mini App checks` на GitHub-hosted runner с Node.js 24, `npm ci`, `npm test`, `npm run build` и проверкой статического `dist/`.
- Локально CI воспроизведён в чистой временной копии исходников: lockfile установился, 5 frontend-тестов и сборка успешно прошли. Запущенный локальный dev-сервер не останавливался.
- GitHub Actions run `31279726442` для commit `83a44d2` успешно завершил одновременно `Python checks` и `Mini App checks`; deploy-задачи в запуске не было.
- В workflow не добавлены secrets, SSH, доступ к VPS, Google Calendar, GitHub Environment или production. `main` не изменялся.
- Изолированный HTTPS preview и production-выпуск не начаты: они потребуют отдельного согласования инфраструктуры и авторизации владельца для открытых GitHub Environment/secrets/protection вопросов.

## 9 августа 2026 — этап 6, подзадача 6.2 начата: проектирование HTTPS preview

- Подготовлен [детальный план изолированного HTTPS preview](docs/ЭТАП_6_2_HTTPS_PREVIEW_ПЛАН.md) без изменения внешней инфраструктуры.
- Рекомендован отдельный preview-поддомен `calendar-dev.yibogdanovskaya.ru`, test bot, тестовая SQLite-база, отдельная loopback ASGI-служба и отдельный тестовый Google Calendar.
- Установлено ограничение: текущий Apps Script gateway не принимает calendar ID из приложения, поэтому его URL и secret нельзя использовать в preview. Нужен отдельный test gateway/secret или отдельный OAuth token только для тестового календаря.
- DNS, BotFather, VPS, Nginx, systemd, секреты, GitHub Environment, `main` и production не менялись. Следующее действие требует готовности внешних тестовых ресурсов и отдельного разрешения на серверные изменения.
