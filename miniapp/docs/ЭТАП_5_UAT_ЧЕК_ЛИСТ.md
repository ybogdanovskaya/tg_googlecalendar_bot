# Этап 5 — локальная интеграция и UAT

Статус: локальная часть завершена 8 августа 2026 года. Этот этап не использовал production-базу, рабочий Google Calendar, VPS или настоящий Telegram-бот.

## Границы проверки

Локальная проверка состоит из двух независимых уровней.

| Уровень | Что проверяется | Среда |
| --- | --- | --- |
| Автоматический | API, роли, CSRF, ownership, безопасные ответы, пользовательские и административные экранные переходы | временная SQLite-база, тестовый Calendar client, mock HTTP-ответы |
| Ручной | Telegram WebView, настоящее подписанное `initData`, responsive-верстка, браузеры и устройства | отдельный HTTPS preview, не production |

Подделка или отключение проверки `initData` для ручного просмотра не допускается. До появления отдельного HTTPS preview вместо неё проверяются только изолированные тесты.

## Автоматические критерии

- [x] Проектная проверка секретов не находит значений в отслеживаемых файлах.
- [x] Python-код компилируется; регрессионные и HTTP contract-тесты проходят на временных данных.
- [x] Поддельные, просроченные и отсутствующие Telegram-данные не дают сессию.
- [x] Пользователь не получает чужую заявку; пользовательская роль не получает административный API.
- [x] API не возвращает Google event ID, детали занятых интервалов или содержимое чужого календаря.
- [x] Frontend собирается в статический `dist/` и не требует Node.js runtime после сборки.
- [x] Frontend-проверки проходят сценарии запуска через Telegram, пользовательской навигации и server-side роли администратора.

## Ручной чек-лист для preview

Этот раздел будет выполнен только после отдельного решения о тестовом HTTPS-адресе и тестовом Telegram-боте.

- [ ] Android Telegram: запуск, safe-area, навигация и создание заявки.
- [ ] iOS Telegram: запуск, клавиатура в формах, выбор даты и времени.
- [ ] Telegram Desktop: пользовательский и административный режимы.
- [ ] Браузер desktop/tablet: адаптивность, клавиатурный фокус и читаемость.
- [ ] Реальная подпись `initData`: пользовательская роль и административная роль определяются сервером.
- [ ] Ручная заявка, серия, перенос и отмена проверяются только с тестовым календарём.
- [ ] Повторная отправка, потеря сети, истёкшая сессия и занятый слот имеют понятное безопасное сообщение.
