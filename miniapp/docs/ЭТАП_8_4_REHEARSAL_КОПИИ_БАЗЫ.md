## Найденные и устранённые проблемы

1. У production virtualenv закономерно отсутствовали зависимости Mini App, в частности FastAPI: действующий `main` ещё не выпускал Mini App. Для rehearsal использована отдельная временная среда; рабочая среда бота не менялась.
2. API не должен зависеть от доступности необязательного локального `.env` в production. Добавлено безопасное поведение: недоступный developer `.env` игнорируется, а реальные настройки по-прежнему берутся из защищённого systemd env-файла. Исправление покрыто автоматическим тестом.

Во время rehearsal не выполнялись пользовательские или административные API-запросы, поэтому Google Calendar и данные рабочей базы не изменялись.

## Важный вывод перед выпуском

Перед будущим production release нужен отдельный этап P2.5: безопасное обновление Python-зависимостей. Текущий deploy сознательно останавливается при изменении `requirements.txt`; это предотвращает непроверенное изменение работающей virtualenv, но для Mini App необходимо реализовать проверяемое создание новой venv и её атомарное переключение с rollback.

До P2.5 нельзя включать production API/service и нельзя выполнять release Mini App из `main`.
