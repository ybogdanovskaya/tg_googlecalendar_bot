- Versioned restricted deploy entrypoint совпадает с проверенной версией `dev`, проходит `bash -n`; резервная серверная копия предыдущей версии сохранена.

- Последние CI для `dev` завершились успешно.

## Намеренно неактивный HTTPS-маршрут

Сейчас в Nginx включён только временный ACME-site для домена. Поэтому запрос к `https://calendar.yibogdanovskaya.ru` получает сертификат default-сайта и не проходит обычную TLS-проверку. Это ожидаемо до релиза, поскольку полный site-конфиг специально не включался, чтобы нельзя было случайно открыть недовыпущенную Mini App.

Сам сертификат домена действителен и сохранён на VPS. В момент выпуска после успешного deploy потребуется включить подготовленный полный Nginx-site, проверить конфигурацию и выполнить controlled reload. Только после этого HTTPS станет доступен внешнему Telegram-клиенту.

## Утверждённый порядок будущего выпуска

Следующий этап выполняется только после нового явного подтверждения владельца:

1. проверить diff и создать/одобрить PR `dev` → `main`;
2. выполнить merge в `main` и вручную одобрить production workflow в GitHub Environment;
3. дождаться deploy с новой API-версией, статическим frontend, резервной копией базы и health-check;
4. включить подготовленный Nginx-site, проверить `nginx -t`, выполнить reload и проверить публичный HTTPS/API;
5. включить и проверить `calendar-miniapp.service` (если deploy этого не сделал);
6. задать production URL для кнопки Mini App в BotFather и провести Telegram UAT;
7. при любой проблеме воспользоваться сохранёнными code/database/venv/entrypoint backup до продолжения.

До этого порядка не нужно включать Nginx-site, API service или production-кнопку BotFather вручную.
