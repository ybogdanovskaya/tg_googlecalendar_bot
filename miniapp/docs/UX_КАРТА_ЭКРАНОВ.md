# UX-карта Telegram Mini App

Статус: этап 1 завершён, 8 августа 2026 года. Документ описывает интерфейс до разработки и не меняет текущий Telegram-бот.

## 1. Принципы интерфейса

- Один Mini App, две server-side роли: `USER` и `ADMIN`.
- Mobile-first: в Telegram на телефоне пользователь проходит сценарий одной рукой и без горизонтальной прокрутки. На планшете и desktop тот же URL использует широкую компоновку.
- Русский язык; все тексты выносятся в словарь для будущей локализации.
- Дизайн: светлая деловая поверхность, глубокий зелёный акцент, спокойные серо-зелёные границы, системный sans-serif. Используются Telegram theme variables как безопасная адаптация к светлой/тёмной теме.
- UI никогда не объясняет занятость чужим событием: только «нет доступного времени» либо «слот уже занят».
- Любая mutation получает понятный pending-state, результат, возможность повторить безопасный запрос и возврат к исходному экрану.

## 2. Навигация

### Телефон

| Роль | Нижняя навигация | Дополнительно |
| --- | --- | --- |
| Пользователь | Главная · Мои встречи · Ещё | На главной — основное действие «Записаться» |
| Администратор | Главная · Заявки · Управление · Ещё | В «Управлении» — встречи, серии, настройки, статистика, интеграция |

`Ещё` содержит помощь, политику конфиденциальности и удаление данных. Экран формы открывается полноэкранно с понятной кнопкой «Назад»; прогресс показывается в создании заявки.

### Планшет и desktop

Слева постоянная навигация, справа контент. В списках заявок и встреч используется master-detail: список остаётся слева, открытая карточка — справа. Формы редактирования открываются в основной области, опасные действия — в диалоговом подтверждении.

## 3. Общая карта

```text
Запуск
  ├─ Проверка Telegram / восстановление сессии
  ├─ Ошибка запуска вне Telegram / истёкшая сессия
  ├─ Политика и согласие (только если отсутствует)
  └─ Главная
      ├─ Пользовательские сценарии
      │   ├─ Записаться
      │   ├─ Мои встречи
      │   ├─ Помощь и политика
      │   └─ Удаление данных
      └─ Администратор: Управление
          ├─ Dashboard и заявки
          ├─ Ручные встречи и серии
          ├─ Настройки записи и доступности
          ├─ Статистика
          └─ Google / синхронизация
```

## 4. Пользовательские экраны и переходы

### 4.1 Запуск и согласие

| Экран | Содержание | Действия |
| --- | --- | --- |
| Splash | Нейтральный индикатор «Открываем календарь» | Проверка `initData` и сессии; не показывает персональные данные до ответа API |
| Недоступно | Инструкция открыть приложение из Telegram / повторить | `Повторить`, `Закрыть` |
| Политика | Версия политики, краткое объяснение целей обработки и ссылка на полный текст | `Согласен`, `Назад` |
| Главная | Приветствие по серверным данным, карточка «Записаться», краткий статус ближайшей встречи | Запись, переход к моим встречам |

Если согласие уже принято через бот или Mini App, экран согласия пропускается. Отказ не удаляет исторические данные, но блокирует создание новой заявки и предлагает вернуться к политике.

### 4.2 Создание заявки

```text
Длительность → Дата → Часть дня и слот → Данные встречи → Проверка → Успех
```

| Шаг | Элементы | Правила и ошибки |
| --- | --- | --- |
| Длительность | Карточки доступных длительностей | Значения приходят от backend, не зашиваются во frontend |
| Дата | Календарная сетка в пределах горизонта; закрытые даты неактивны | Не вычислять свободное время на клиенте |
| Часть дня и слот | Чипы «утро/день/вечер» с количеством допустимых слотов; кнопки времени | API возвращает только разрешённые свободные слоты; при `SLOT_UNAVAILABLE` вернуться к этому шагу и обновить список |
| Данные | Имя, email, тема; описание и место/ссылка необязательны | Inline validation, email без кода, черновик только в памяти вкладки |
| Проверка | Карточка даты, времени, длительности и всех введённых данных; срок резерва | Явное подтверждение «Отправить заявку» |
| Успех | Статус «На согласовании», срок активного резерва, ссылка «Мои встречи» | Повторное нажатие не создаёт заявку дважды |

При потере сети данные текущей формы остаются только в памяти вкладки; перед отправкой пользователь видит возможность повторить. Не сохранять в `localStorage` email, тему или описание.

### 4.3 Мои встречи

Список группируется: «Ближайшие», «На согласовании», «Завершённые». Карточка показывает только данные заявки пользователя и понятный статус.

| Состояние | Доступные действия |
| --- | --- |
| На согласовании с активным резервом | Изменить, отменить заявку |
| На согласовании с истёкшим резервом | Просмотреть; администратор ещё может предложить время или согласовать при свободном слоте |
| Предложены альтернативы | Открыть варианты, принять один или отклонить все |
| Создаётся событие | Только обновить статус; повторная операция заблокирована |
| Назначена | Запросить перенос или отмену; посмотреть итоговые данные |
| Отклонена / отменена / завершена | Просмотреть историю |

Форма изменения pending-заявки использует тот же путь выбора времени. При сохранении backend повторно проверяет доступность и освобождает старый слот только после успеха.

### 4.4 Альтернативы, перенос и отмена

- Альтернативы: карточки с датой, временем и длительностью; принятие требует серверной проверки слота. При конфликте варианты обновляются без раскрытия причины занятости.
- Перенос назначенной встречи: пользователь выбирает новый допустимый слот и отправляет запрос; старая встреча не меняется до решения администратора.
- Отмена назначенной встречи: пользователь видит последствия и создаёт запрос; календарь не изменяется автоматически.

### 4.5 Privacy и помощь

Экран удаления данных содержит два изолированных сценария: отменить будущие встречи и удалить данные; либо сохранить будущие встречи с минимальными данными до их завершения. Перед подтверждением выводятся последствия и число затронутых будущих встреч, но не чужие данные.

## 5. Административные экраны

| Раздел | Основные элементы | Ключевые действия |
| --- | --- | --- |
| Dashboard | Счётчики заявок, ожидающие действия, ближайшие встречи, проблемы синхронизации | Перейти к требующему внимания объекту |
| Заявки | Фильтры статуса/периода, список, карточка пользователя | Согласовать, отредактировать, предложить альтернативы, отклонить, удалить по правилам retention |
| Ручные встречи | Список и редактор разовых событий | Создать с гостем/без, задать блокировку, проверить конфликт, отдельно подтвердить пересечение |
| Серии | Список серий, карточка и календарь повторений | Создать/изменить/отменить серию, изменить или отменить одно повторение |
| Доступность | Окно записи, длительности, шаг, минимальный срок, горизонт, закрытые даты | Сохранить серверно валидированное значение |
| Напоминания и тексты | Интервалы уведомлений и версия политики | Изменить с audit trail |
| Статистика | Период, агрегаты по заявкам/встречам/длительности | Изменить период; выгрузки не входят в этап 1 |
| Google и синхронизация | Только состояние соединения, ошибки, дата проверки | Перейти к безопасной повторной проверке/инструкции; не показывать события календаря |

### Административные подтверждения

Перед созданием пересекающейся встречи, отменой серии, удалением объекта, обработкой запроса отмены/переноса и изменением критичных настроек показывается диалог с последствиями. Кнопка действия недоступна до завершения исходного запроса. Все изменения журналируются backend.

## 6. Состояния, обязательные на каждом экране

| Состояние | Поведение |
| --- | --- |
| Загрузка | Skeleton для списков; заблокированная кнопка с индикатором для mutation |
| Пустой результат | Причина простыми словами и следующая полезная кнопка |
| Нет сети | Сохранить форму в памяти, показать «Повторить»; не обещать сохранение на сервере |
| Слот занят | Вернуть на выбор времени, получить новый список слотов |
| Сессия истекла | Повторить Telegram authorization; не терять текущий in-memory draft |
| Google временно недоступен | Сообщить без деталей; разрешить повтор после безопасного интервала |
| Нет доступа | Не раскрывать существование объекта; вернуться в разрешённый раздел |

## 7. Доступность и адаптивность

- Минимальная интерактивная область 44×44 px, видимый focus, семантические label и error-message.
- Цвет не является единственным носителем статуса; используются текст и иконка.
- Все формы управляются клавиатурой на desktop; даты и время имеют доступные подписи.
- Учитываются safe-area Telegram, тёмная тема и динамическая высота WebView.
- Проверка: Android Telegram, iOS Telegram, Telegram Desktop и современные браузеры для desktop/tablet.
