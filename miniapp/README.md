# Telegram Calendar Mini App

Статус: этапы 0–5 завершены локально; подзадача 6.1 — frontend CI — завершена. Изолированный HTTPS preview технически развёрнут на VPS; требуется назначить URL тестовому боту в BotFather и пройти Telegram UAT. Production-развёртывание не начиналось.

## Цель

Создать мобильный интерфейс внутри Telegram для существующего сервиса записи на встречи. Mini App должен использовать тот же backend, те же правила доступности и ту же базу, что и чат-бот.

## Уже принято

- папка Mini App находится в текущем репозитории;
- разработка ведётся через `dev` и `feature/miniapp-*`;
- production frontend будет статическим;
- сборка выполняется в GitHub Actions;
- Nginx отдаёт готовые файлы;
- Docker и постоянный Node.js runtime на VPS не требуются;
- рекомендуется отдельный HTTPS-поддомен;
- Telegram-авторизация проверяется backend;
- Google Calendar остаётся скрытым от пользователей.

## Принятое проектное решение

Полное решение по стеку, API, безопасности, карте экранов, этапам и критериям приёмки находится в [docs/АРХИТЕКТУРА_И_ПЛАН.md](docs/АРХИТЕКТУРА_И_ПЛАН.md). Рекомендуется один role-aware Mini App: React + TypeScript + Vite для статического frontend и versioned REST API общего Python backend. Реализация backend, CI и сервера потребует отдельного согласования, поскольку затронет файлы вне `miniapp/`.

Итоговый статус preview, чек-лист готовности и безопасный план будущего production-выпуска находятся в [docs/ЭТАП_7_ГОТОВНОСТЬ_К_PRODUCTION_И_ПЛАН_ВЫПУСКА.md](docs/ЭТАП_7_ГОТОВНОСТЬ_К_PRODUCTION_И_ПЛАН_ВЫПУСКА.md). До выполнения внешних условий из этого документа `main` и production не изменяются.

Решение о Telegram-only доступе и точный проект будущего production-маршрута зафиксированы в [docs/ЭТАП_8_1_PRODUCTION_МАРШРУТ.md](docs/ЭТАП_8_1_PRODUCTION_МАРШРУТ.md). Это проектирование: DNS, production-сервер и `main` в рамках него не меняются.

Подготовленные, но ещё не применённые CD/systemd/Nginx изменения описаны в [docs/ЭТАП_8_2_CD_И_КОНФИГУРАЦИЯ.md](docs/ЭТАП_8_2_CD_И_КОНФИГУРАЦИЯ.md).
