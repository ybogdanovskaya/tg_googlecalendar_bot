# CI/CD для Telegram Calendar Bot

## Ветки

- `feature/*` — отдельная доработка;
- `dev` — интеграционная версия для общей проверки;
- `main` — только проверенная production-версия.

Рекомендуемый маршрут изменения: `feature/*` → `dev` → `main`.

## CI

Workflow `CI` запускается при изменениях в `main`, `dev`, `feature/*`, `hotfix/*` и в pull request к `main` или `dev`.

Проверки:

1. установка Python 3.12 и зависимостей;
2. проверка согласованности зависимостей;
3. поиск случайно добавленных токенов, закрытых ключей и файлов с секретами;
4. компиляция Python-файлов;
5. полный набор автоматических тестов.

CI выполняется на GitHub-hosted runner и не потребляет ресурсы VPS.

## Production CD

Workflow `Deploy production` запускается вручную только из ветки `main`.

Перед развёртыванием он повторно выполняет все проверки. Задание развёртывания использует защищённое GitHub Environment `production` и ждёт ручного подтверждения владельца.

На сервер передаётся архив только с отслеживаемыми файлами проекта. Серверный сценарий:

1. блокирует параллельные развёртывания;
2. проверяет размер и структуру архива;
3. повторно запускает компиляцию и тесты во временном каталоге;
4. запрещает автоматическое обновление Python-зависимостей;
5. сохраняет предыдущий код;
6. останавливает только Telegram-бота;
7. создаёт согласованную копию SQLite;
8. устанавливает новую версию и запускает бота;
9. запускает штатный health-check;
10. при ошибке восстанавливает предыдущий код и базу.

Сайт и Nginx при развёртывании Telegram-бота не перезапускаются.

## Секреты environment `production`

- `PROD_SSH_HOST` — IP или имя VPS;
- `PROD_SSH_USER` — отдельный пользователь развёртывания;
- `PROD_SSH_PRIVATE_KEY` — отдельный закрытый ключ только для CI/CD;
- `PROD_SSH_KNOWN_HOSTS` — закреплённый публичный ключ VPS.

Личный SSH-ключ владельца и рабочие секреты Telegram/Google в GitHub Actions не используются.

## Изменения зависимостей

Если изменён `requirements.txt`, автоматическое production-развёртывание остановится до замены файлов. Обновление зависимостей выполняется отдельной контролируемой процедурой с проверкой совместимости и отката.
